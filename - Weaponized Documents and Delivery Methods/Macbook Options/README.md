An interesting implicaiton of RMM abuse, is that Apple introduces several obstacles to delivering malware to MacBook devices, when compared to Windows. For Microsoft Windows, you can simply create something malicious, and if it is not detected as bad and if application control is not in palce, it will run. Of course, there is userland vs. admin and Mark-of-the-Web/UAC to contend with there. Still, the bar to get some sort of code to run is often low. 

For weaponized office documents they seem to run in a sandbox on MacBook, moving it removes the "This Document" trigger that runs on open, and all of the really interesting command capabilities have been depricated (I was able to run calc, but VBA could not download a file, establish a network connection, or run anything). There is a trick still in Word where you can press Command+Fn+F9 and a set of braces will occur in the word doc, and then you can type MACROBUTTON followed by the macro you want to run, then press Fn+F9 again. An inconspicuous string of text called 'Run Automation' will appear, which with an appropriate lure may get tricked and trigger the macro, but again - there is nothing that intresting that I could find to trigger. MS Excel was a little more promising, with the ability to add a button to trigger a macro, but have not tested that much yet because there does not seem to be very much that can be done from the macros without a new sandbox escape. 

It is easy enough to create malicious sh scripts, apps, or DMGs and they will run just fine on the host they are created on. Move the App or DMG to another host without signing and registering it, and it is untrusted and labled as potential malware right away. Languages such as Go and Python also work, but most scenarios with Go/Python/sh require chmod +x, followed by ./ from terminal (and I could write a script to disk via VBA, but could not run it). Having to run from terminal with multiple steps is not the easiest Social Engineering bar for a red teamer, compared with Windows where you can open a document and at worst maybe get a UAC prompt.

Simply put, Apple has taken several steps for MacBook that make it harder to deliver malware to hosts, compared with Microsoft Windows, all things equal. 

This is where RMM is interesting, because it is valid and trusted as legitimate software that people expect to seamlessly deploy from a customer tenant.
